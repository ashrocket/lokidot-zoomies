# Windows preview

The Windows app lives in `windows/LokiDot.Windows`; it does not change the Mac build. It targets .NET 10 WPF and publishes a self-contained x64 app for supported Windows versions. [.NET 10 is LTS through November 14, 2028](https://dotnet.microsoft.com/en-us/platform/support/policy/dotnet-core). Windows 11 x64 is the intended first manual-test target.

The packaging project names exactly eight public artwork files: `manifest.json` and `atlas.png` for Whippet, Beagle, Robot Loki and the authorized Loki Vampire pack. Neither personal packs nor recordings are inputs. Runtime imports validate and hold a local snapshot in memory. They are not copied into the installation or published. Packs contain no executable fields and cannot initiate network requests. Update checks use only the fixed public GitHub endpoints described below; there is no telemetry or authentication.

The preview provides the dog/all picker, Zoomies/Circle/Prance, Start, Pause/Resume, Repeat and Add your dog. A lap takes 16/8/7 seconds, followed by 24 seconds of rest when Repeat is checked. Motion uses a sampled closed Bézier route with distance easing, authored left/right crossfades and pet-v2 jump frames. Prance rejects any selected pack without authored jumping frames, with a useful error before replacing the current routine. Windows animation effects being disabled gives a stationary idle pose. The controller receives ordinary interaction; bank and squash transforms apply to an inner artwork Grid inside a padded square window, leaving the Window transform at identity; pet windows use transparent layered WPF windows, `WS_EX_TRANSPARENT`, `WS_EX_NOACTIVATE`, `WS_EX_TOOLWINDOW`, `HTTRANSPARENT` and `MA_NOACTIVATE`.

## Pack validation

The loader accepts schema 1 `zoomies-v1` and `pet-v2`, rejects missing, duplicate and unknown fields, and never interprets data as commands. It bounds JSON to 32 KiB and PNG to 16 MiB, checks PNG signature, chunk checksums, single-image/non-APNG structure and final end marker before decoding. Dimensions are limited to 4096 per side and 8,388,608 pixels total, with 8–512 pixel cells. Declared frames must fit the grid without overlap, contain visible pixels and a fully transparent background pixel. pet-v2 requires the exact 1536 × 2288 grid, row/count mapping and transparent unused cells. FPS is 0.5–30; frame counts are 1–64 for idle and 2–64 otherwise.

The image must be a plain PNG filename. Selected folders and parents cannot be reparse points. Directory/file handles exclude delete sharing during reads; file opens use `FILE_FLAG_OPEN_REPARSE_POINT`, reject non-disk/reparse/directory files, and compare resolved file paths with the held folder. Only bounded regular-file snapshots reach the decoder. Broken paths, corrupt data and missing files produce import errors.

## Build and installer

Run from the repository root on Windows with the .NET 10 SDK:

```powershell
./windows/build.ps1
./windows/test-installer.ps1
```

`build.ps1` publishes `win-x64` with the runtime, uses fresh per-run staging, checks exactly four public pack directories and eight files recursively (rejecting nested directories, links and reparse points), and creates `windows/artifacts/LokiDot-Zoomies-win-x64.zip`, `.msi` and `SHA256.txt`. Complete outputs remain in `windows/artifacts/runs/<id>`; `publish-path.txt` and `run-path.txt` identify the current successful build for verification. Stable download copies are written only after both packages succeed, and earlier run directories are preserved. The MSI uses ordinary Windows Installer components, a Start Menu shortcut and major-upgrade detection. It installs per machine under Program Files and requires elevation. It has no services, autostart, Burn bootstrapper, extensions or custom executable install actions. Removing the MSI removes its installed files, shortcut and registry marker. The portable ZIP needs no installer. Neither artifact is code signed in this preview.

The build tool is deliberately pinned to [WiX 5.0.2's official release](https://github.com/wixtoolset/wix/releases/tag/v5.0.2) and [NuGet package](https://www.nuget.org/packages/wix/5.0.2), whose [source license is MS-RL](https://github.com/wixtoolset/wix/blob/v5.0.2/LICENSE.TXT). This tool predates the WiX 6/7 maintenance-subscription terms. It runs only at build time; no WiX runtime is installed. `--allow-roll-forward` lets the .NET tool use the installed SDK runtime. Official [Files harvesting](https://docs.firegiant.com/wix/schema/wxs/files/) supports the recursive payload syntax used here.

WiX 5's [consumer security servicing ended February 5, 2026](https://docs.firegiant.com/wix/). This pinned tooling is a preview limitation that needs a supported packaging decision before production distribution. It is not claimed to be current or supported. Newer WiX adoption must consider its published terms rather than silently upgrading this pin.

## Verification and remaining acceptance

`.github/workflows/windows.yml` runs on `windows-2025`, builds both downloads, runs the portable app's `--self-test`, installs the MSI on a clean runner, repeats the installed app's self-test, launches its normal entry point, closes it normally and uninstalls. Nonzero results fail CI. Installer logs, test receipts and render PNGs are uploaded even when checks fail; download artifacts are published only after the checks pass.

Self-test covers all bundled packs, valid zoomies-v1 input, unknown/executable/duplicate/missing JSON fields, filename traversal, frame/fps/overlap/extent limits, empty/opaque cells, PNG corruption/truncation/trailing/size limits, bounded local loads and a junction rejection fixture. Motion is sampled across landscape, portrait and small bounds for finite, bounded positions and closed endpoints. Self-test also rejects simple-pack Prance, including mixed All dogs selections. WPF smoke checks create the controller and pet, save offscreen render images, inspect rendered alpha, verify the nonidentity artwork transform and unclipped padded bounds across routines/screen fixtures, and read native no-activate/click-through flags. MSI checks confirm installed files and Start Menu shortcut, app startup and normal exit, and removal of files/shortcut/registry marker.

These are automated checks, not proof that pixels look correct on a real desktop or that clicks pass through to another application. Review uploaded screenshots, then manually test motion, actual focus preservation/click-through, Pause/Resume, rest timing, reduced motion, imported packs, scaling, fullscreen behavior and uninstall on a Windows desktop. The first preview uses the primary work area captured at Start, persists only the automatic update-check preference; other settings/imports last for the session, and does not include Mac menu-bar or movie-export features. Mixed DPI and display changes during a routine remain unverified. No Windows compilation or execution is claimed from a macOS-only static review.

## Updates with confirmation

Version 1.3.2 adds a Check for Updates button and a saved Automatically check for updates checkbox, on by default. Automatic checks run 15 seconds after launch and daily while the app is open. Uncheck the box to disable them. Background offline, rate-limit and malformed-feed errors stay silent; manual checks show an error or an up-to-date result. Automatic checking fetches metadata only. Nothing is downloaded or executed until the owner presses Download and Install in a dialog showing the installed and available versions and the destination. Later closes the dialog without downloading.

The feed is fixed at `https://api.github.com/repos/ashrocket/lokidot-zoomies/releases/latest`, with no credentials or cookies. Metadata is capped at 1 MiB and a 20-second request deadline; metadata redirects are rejected. Stable tags must be exactly `vMAJOR.MINOR.PATCH`, without prerelease/build suffixes, leading zeros or overflowing components. Draft/prerelease releases are rejected and versions compare numerically against the compiled application version. Release URLs must name this repository and tag. Exactly one `uploaded` asset named `LokiDot-Zoomies-win-x64.msi` must have the exact expected repository/tag download URL, a positive declared size at most 512 MiB and a mandatory `sha256:` digest containing 64 hexadecimal digits. This follows the [GitHub release asset API's digest and browser_download_url fields](https://docs.github.com/en/rest/releases/assets).

After confirmation, downloads have a five-minute deadline, at most five redirects, and exact HTTPS host checks for `github.com`, `release-assets.githubusercontent.com`, `objects.githubusercontent.com` and `github-releases.githubusercontent.com`. Alternate ports, credentials, fragments, unrelated GitHub asset routes and other hosts/protocols are rejected. Stream writes stop at the declared size. The staged MSI retains an Internet-zone `Zone.Identifier` marker for Windows security/reputation prompts. Both the received stream and the final staged file must match the exact size and SHA-256 before installation. The updater creates a unique directory under local AppData with a protected ACL for the current account, SYSTEM and Administrators, rejects network/reparse storage, and holds a read handle denying writes/deletion while a separate Windows helper takes over. Successful installer files stay there for Windows Installer; there is no broad cache cleanup.

The app starts the fixed System32 Windows PowerShell host with an immutable encoded helper and a bounded, data-only JSON message on stdin. No profile is loaded, module autoloading is disabled, and JSON parsing is imported explicitly from the trusted Windows utility module. There is no execution-policy bypass or mutable staged script. The helper independently validates the path/version/size/hash, opens its own read handle denying writes/deletion, and starts the fixed system `msiexec.exe` with `/i`, a validated quoted absolute MSI path and `/norestart`, without shell execution or quiet-mode options. Windows PowerShell's .NET Framework host lacks `ArgumentList`; quotes/control characters are rejected before native command-line quoting. A nonce-bound stdout acknowledgement confirms helper lock ownership before Zoomies closes. The helper holds that lock through Windows Installer's process exit, independently of Zoomies. Missing/invalid acknowledgement never kills a helper that may have started installation; the parent retains its lock while awaiting helper exit and reports an unconfirmed handoff rather than definite installation failure. [Windows Installer](https://learn.microsoft.com/en-us/windows/win32/msi/standard-installer-command-line-options) shows its normal UI and security prompts and finishes the installation after Zoomies closes normally. This per-machine MSI requires administrator approval and installs under Program Files, including from the portable ZIP. Zoomies does not restart automatically. Starting the installer is not proof installation finished successfully.

Offline update self-tests inject metadata, HTTP responses and small byte streams. They cover stable/numeric versions, wrong repositories/tags/assets, absent or malformed digests, duplicate assets/fields, upload state, size limits, metadata/asset redirects, bounded streams, truncation, tampering, held-file write protection, consent gates and native installer arguments. They never make a real request or launch an installer. CI also starts the actual encoded Windows helper against a fixed harmless wait stand-in, closes the parent verifier, proves overwrite/delete/rename remain denied until stand-in completion, and checks helper-side size/hash failures. The stand-in can only suppress installation; it cannot select another executable. The WPF self-test disables updater scheduling. CI still builds the ZIP/MSI, verifies portable `SHA256.txt` entries, and exercises actual MSI install, startup, normal close and uninstall. Network update UX and a real approved upgrade still require manual Windows acceptance.

Loki Vampire uses `zoomies-v1` and has no jumping artwork. Its own Prance and All dogs Prance show a useful rejection before changing the current routine; Zoomies and Circle work for all four bundled packs. Self-tests separately verify Prance for the three packs with authored jumping frames.
